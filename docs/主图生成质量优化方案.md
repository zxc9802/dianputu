# 店铺主图生成质量优化方案

> 版本：V1  
> 状态：待执行  
> 日期：2026-05-06

---

## 一、问题描述

当前生成的店铺主图，模块结构是正确的，但不同模块之间的图片**视觉相似度过高**。

典型表现：
- 「活动次图-成分」和「活动次图-效果」构图几乎一样
- 多张图都是"产品居中 + 环绕文字 + 绿色植物背景"的相同模板
- 成分图和效果图的差异仅在于文字内容，视觉主体和布局无法区分

---

## 二、根因分析

### 根因 1：所有模块都注入完整产品 brief

当前 `prompt_builder.py` 的 `build_module_image_prompt` 函数中，每个模块都会收到完整的 `build_product_generation_brief`，包含：
- 核心卖点（全部）
- 核心功效（全部）
- 核心成分（全部）
- 目标人群（全部）
- 使用方法（全部）
- 权威资料（全部）
- 效果数据（全部）

**后果**：AI 生成模型看到这么多信息后，倾向于把所有内容都塞进画面，导致每张图都变成"信息大杂烩"，彼此难以区分。

### 根因 2：模块构图指令太简短，缺乏差异化

以成分图和效果图为例：

| 模块 | 当前 prompt 指令 |
|------|----------------|
| 成分图 | "画面只呈现成分次图，突出核心成分、原料质感和成分标签" |
| 效果图 | "画面只呈现效果次图，突出核心功效、使用收益和可信的效果表达" |

两者都是"突出 XXX"这种泛化表述，**没有告诉 AI 应该用什么样的具体布局**（是左右分栏？上下分区？九宫格？），也没有指定**主视觉元素**应该是什么（原料实物微距？数据图表？人物场景？）。

### 根因 3：没有排斥指令

每个模块没有告诉 AI：
- "这张图不能出现其他模块的元素"
- "不要使用和首图相同的构图"
- "成分图的主体不能是产品瓶身"

AI 在缺乏排斥约束时，会默认使用最"安全"的构图 —— 产品居中 + 环绕文字。

### 根因 4：每张图独立生成，无上下文关联

当前生成流程是 `for` 循环逐张调用 API，每次调用互相独立。AI 不知道前面已经生成了什么样的图，自然无法主动做差异化。

---

## 三、优化方案

### 方案 A：强化 Prompt 构图差异化（推荐优先做）

**改动范围**：仅 `prompt_builder.py`，不动前端和 API 调用流程。  
**预期效果**：每个模块生成的图片在构图、主视觉元素、信息侧重上有明显差异。

#### A1. 新增模块构图配方表（`MODULE_VISUAL_RECIPES`）

为每个模块定义独立的构图方案，包含：构图模板、主视觉元素、产品瓶身在画面中的角色、禁止出现的元素。

| 模块 | 构图模板 | 主视觉元素 | 产品角色 | 禁止出现 |
|------|---------|-----------|---------|---------|
| **白底图** | 纯白居中，无任何装饰 | 产品瓶身 | 唯一主体 | 所有文字、装饰、颜色 |
| **首图** | 产品占画面 60%，右侧或上方放一句话卖点 | 产品大图 + 1 句核心卖点 | 最大主体（居中偏左） | 成分表、数据图表、使用步骤 |
| **次图-成分** | **左右分栏**：左侧原料实物微距特写，右侧成分名+作用卡片 | 原料实物质感（如积雪草叶片、透明液滴） | 缩小放右下角或不出现 | 效果数据百分比、使用步骤、人物 |
| **次图-效果** | **上下分区**：上方肌肤质感/体验感画面，下方数据仪表盘或进度条 | 数据可视化图表、肌肤对比质感 | 缩小放角落作辅助 | 成分详情列表、使用步骤 |
| **次图-使用场景** | **场景化全幅**：人物/手部使用动作占主画面 | 模特手部涂抹、滴管使用、面部护理 | 产品小图嵌入场景中 | 数据图表、成分列表 |
| **活动首图** | 产品居中 + 促销角标 + 卖点 | 产品 + 活动氛围装饰 | 最大主体 | 成分表、数据、使用步骤 |
| **活动次图-成分** | **成分卡片堆叠布局** + 角落活动角标 | 成分卡片 + 原料质感 + 轻活动氛围 | 缩小或不出现 | 效果数据、使用场景 |
| **活动次图-效果** | **数据仪表盘/进度环** + 促销利益点标签 | 数据图表 + 促销标签 | 缩小放角落 | 成分详情、使用场景 |
| **活动次图-使用场景** | **场景图** + 礼盒/活动标签 | 使用场景 + 礼盒氛围 | 产品嵌入场景 | 成分表、数据图表 |

#### A2. 按模块精简注入信息

把当前的"每个模块都注入完整 brief"改为"每个模块只收到它需要的信息子集"：

```
白底图         → 只给：产品名称、规格
首图           → 只给：产品名称、品类、核心卖点（前2个）
次图-成分      → 只给：产品名称、核心成分详情
次图-效果      → 只给：产品名称、核心功效、效果数据
次图-使用场景  → 只给：产品名称、目标人群、使用方法
活动首图       → 只给：产品名称、核心卖点（前2个）
活动次图-成分  → 只给：产品名称、核心成分详情
活动次图-效果  → 只给：产品名称、核心功效、效果数据
活动次图-场景  → 只给：产品名称、目标人群、使用方法
```

#### A3. 新增构图排斥指令

在每个模块的 prompt 末尾加入排斥指令，例如成分图：

```
【构图差异化约束】
- 本图是「成分图」，构图必须使用左右分栏布局：左侧原料微距，右侧成分卡片。
- 不得使用"产品居中 + 环绕文字"的构图（那是首图的专属构图）。
- 画面主视觉是原料实物特写，而不是产品瓶身。
- 不得出现效果数据百分比、使用步骤图示、使用场景人物。
```

#### 涉及文件

| 文件 | 改动内容 |
|------|---------|
| `backend/app/services/prompt_builder.py` | 新增 `MODULE_VISUAL_RECIPES` 构图配方表；新增 `build_module_specific_brief` 按模块精简信息；重构 `_module_requirements` 加入构图和排斥指令；修改 `build_module_image_prompt` 用精简 brief 替换完整 brief |

---

### 方案 B：随机构图变体（可选增强）

为部分模块提供 2-3 种构图变体，每次生成时随机选择一种，避免多次重新生成时总是出同样的构图。

示例 - 成分图的 3 种构图变体：
1. 左右分栏：左侧原料微距实拍，右侧成分卡片
2. 上下分区：上方原料实物平铺俯视图，下方成分说明文字
3. 环形布局：产品小图居中，3 个核心成分卡片围绕排列

#### 涉及文件

| 文件 | 改动内容 |
|------|---------|
| `backend/app/services/prompt_builder.py` | 为每个模块新增 `layout_variants` 列表，在构建 prompt 时随机选择 |

---

### 方案 C：提高 API 超时（配套修复）

当前 `image_model.py` 中 API 超时为 240 秒（4 分钟），调大到 480 秒（8 分钟），避免生成复杂图时超时失败。

#### 涉及文件

| 文件 | 改动内容 |
|------|---------|
| `backend/app/services/image_model.py` | `timeout=240` → `timeout=480` |

---

## 四、执行优先级

| 优先级 | 方案 | 改动量 | 预期效果 |
|-------|------|-------|---------|
| P0 | 方案 A（构图差异化） | 中等，约 200 行 | 效果最明显，每张图构图明显不同 |
| P1 | 方案 C（加超时） | 1 行 | 避免超时失败 |
| P2 | 方案 B（随机变体） | 较小 | 多次生成时不重复 |

---

## 五、验证方式

1. 用同一组产品信息生成一套 5 张主图，对比优化前后的视觉差异
2. 重点检查：成分图 vs 效果图 vs 使用场景图的构图是否明显不同
3. 检查排斥指令是否生效（成分图中不出现效果数据，效果图中不出现成分列表）
