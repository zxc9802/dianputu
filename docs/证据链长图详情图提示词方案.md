# 证据链长图详情图提示词方案

> 版本：V1  
> 状态：方案草案  
> 适用范围：详情图新分支结构选择、资料拆解、模块 brief、主图信息复用、单图生成提示词

---

## 一、目标

新增一套详情图排版结构可选项：

- 默认结构：证据链长图结构，16 屏
- 保留结构：当前标准转化结构，10 屏

新结构不只是多一套模块列表，而是一套从第一步上传资料开始生效的提示词链路：

1. 用户先选择详情图排版结构。
2. 上传资料后，AI 按选中的结构拆解产品信息。
3. 解析结果同时生成详情图模块 brief 和主图/活动主图可复用的共享卖点 brief。
4. 最终生成时，每张图只读取自己的模块 brief，避免内容串屏。

---

## 二、核心流程

推荐流程：

```text
选择详情结构
→ 上传产品图 / 资料 / 报告
→ AI 按所选结构解析资料
→ 用户确认产品信息和结构拆解
→ 选择主图 / 活动主图 / 详情图模块
→ 按模块 brief 生成图片
→ 预览与导出长图
```

关键变化：

- 详情结构选择必须前置到第一步，不能只放在模块选择页。
- 资料解析接口需要接收 `detail_layout_id`。
- 如果用户已解析资料后切换结构，需要重新拆解模块 brief。
- 主图结构仍保持 5 张不变，但主图的信息选择可以读取新分支拆解出的共享卖点。

---

## 三、结构 ID

新分支建议命名：

```text
detail_evidence_chain_16
```

中文名：

```text
证据链长图结构，16 屏
```

保留当前结构：

```text
detail_standard_conversion_10
```

中文名：

```text
标准转化结构，10 屏
```

## 四、AI 解析输出结构

解析阶段建议输出统一 JSON：

```json
{
  "product_info": {
    "product_name": "",
    "category": "",
    "spec": "",
    "core_selling_points": [],
    "functions": [],
    "ingredients": [
      {
        "name": "",
        "benefit": ""
      }
    ],
    "target_users": [],
    "usage_method": [],
    "authority_assets": [],
    "effect_claims": [
      {
        "claim": "",
        "value": "",
        "source_type": ""
      }
    ],
    "material_highlights": [],
    "confirmation_status": "pending"
  },
  "cross_image_brief": {
    "hero_claim": "",
    "primary_pain": "",
    "primary_function": "",
    "auxiliary_function": "",
    "ingredient_priority": [],
    "proof_points": [],
    "usage_scene": "",
    "texture_keywords": [],
    "compliance_warnings": []
  },
  "detail_layout_brief": {
    "layout_id": "detail_evidence_chain_16",
    "modules": [
      {
        "module_id": "",
        "module_name": "",
        "page_task": "",
        "headline_direction": "",
        "primary_visual": "",
        "required_content": [],
        "forbidden_content": [],
        "data_source_note": "",
        "compliance_boundary": ""
      }
    ]
  }
}
```

字段职责：

- `product_info`：事实库，保存产品基础资料、成分、功效、数据、用法。
- `detail_layout_brief`：详情图结构拆解，严格按所选详情结构生成。
- `cross_image_brief`：共享卖点层，供主图、活动主图和详情图首屏共同使用。

## 五、资料解析提示词

```text
你是护肤电商详情页策划，请根据用户上传的产品图、资料、报告和说明文字，按“证据链长图结构，16 屏”拆解商品详情页。

你需要先提取真实产品信息，再把卖点、痛点、成分、数据、背书、使用方法分配到 16 个详情图模块。

必须输出 JSON，不要输出解释文字。

输出内容包括：
1. product_info：产品事实库。
2. cross_image_brief：主图、活动主图和详情首屏共用的浓缩卖点。
3. detail_layout_brief：按 16 屏结构拆解的模块 brief。

重要规则：
- 用户上传资料优先，AI 只能在资料不足时做护肤电商常识级补全。
- AI 推断内容必须使用温和、泛化表达，不得伪装成真实资料。
- 不得编造真实机构、检测编号、专利号、临床数据、医生背书、真实用户评价。
- 不得出现治疗、治愈、医学疾病改善、绝对化承诺。
- 没有真实数据时，不得编造百分比，只能使用体验型表达。
- 所有文案必须适合中文电商图片使用，短句化、消费者能理解。

请严格按以下 16 个模块拆解：
1. 首屏爆点
2. 痛点放大
3. 产品解决方案
4. 差评与竞品对比
5. 真人实测引入
6. 效果对比验证
7. 研发体系背书
8. 核心成分一机制
9. 核心成分一证明/配比
10. 核心成分二机制
11. 辅助功效机制
12. 辅助功效验证
13. 真人反馈合集
14. 质地与肤感展示
15. 品牌感/香氛/情绪价值
16. 使用方法
```

## 六、共享卖点层设计

`cross_image_brief` 用来解决“新分支拆解结果能不能覆盖主图”的问题。

结论：

- 可以覆盖主图的信息选择。
- 不应该覆盖主图的模块结构。

主图仍保持当前 5 张结构：

1. 白底图
2. 首图
3. 成分图
4. 效果图
5. 使用场景图

但主图生成时读取 `cross_image_brief`：

| 主图模块 | 使用的新分支信息 |
| --- | --- |
| 首图 | `hero_claim`、`primary_pain`、`primary_function` |
| 成分图 | `ingredient_priority` |
| 效果图 | `primary_function`、`proof_points` |
| 使用场景图 | `usage_scene`、`texture_keywords` |
| 活动主图 | `hero_claim`、`proof_points`、`promotion_info` |

这样新分支的结构化拆解能反哺整套图片，但不会把主图也变成 16 屏详情结构。

## 七、16 屏模块提示词

### 1. 首屏爆点

```text
生成一张商品详情页首屏。主视觉为 {product_name} 产品大图，占画面 35%-50%，搭配清透液体、成分球、柔和商业光影。
标题突出 {core_selling_point_1}，副标题说明 {target_user_pain}。
底部可放 2-3 个可信卖点标签，如 {function_1}、{function_2}、{ingredient_1}。
整体像高转化详情页第一屏，不做成普通氛围海报。
```

### 2. 痛点放大

```text
生成一张用户痛点页。上方大标题描述目标用户的核心困扰：{target_user_pain}。
中间使用 4-6 个局部肌肤问题卡片或场景卡，例如粗糙、暗沉、出油、干燥、毛孔、泛红等，按产品资料选择。
画面要让用户觉得“这就是我的问题”。
可以有专家/顾问形象作为轻背书，但不得伪造医生身份或医疗诊断。
```

### 3. 产品解决方案

```text
生成一张产品方案页。页面任务是从痛点转入 {product_name} 的解决逻辑。
主视觉为产品 + 核心成分/质地展开。
左侧或周围放 3-4 个解决路径：{function_1}、{function_2}、{function_3}、{ingredient_system}。
标题强调“针对问题，给出复合护理方案”。
不要提前塞入大量检测数据。
```

### 4. 差评与竞品对比

```text
生成一张竞品对比页，参考“普通同类产品 vs 本品方案”的结构。
左侧或两侧表现普通同类产品常见不足：清洁不彻底、肤感厚重、短效、刺激、拔干、难吸收等，按 {category} 选择。
右侧突出 {product_name} 的差异化优势：{core_selling_point_1}、{core_selling_point_2}、{function_1}。
不得出现真实竞品品牌、真实差评截图或攻击性语言。
```

### 5. 真人实测引入

```text
生成一张真人使用/体验引入页。
主视觉为真实自然的人物使用产品场景，突出 {target_users} 的状态变化期待。
左侧可放“使用前困扰”短标签，右侧或下方放产品。
标题强调 {core_selling_point_1} 带来的体验变化。
人物真实、皮肤自然，不要过度磨皮，不做医疗治疗前后图。
```

### 6. 效果对比验证

```text
生成一张效果验证页。
上半部分展示局部使用前后对比卡片，下半部分展示简洁数据图或趋势图。
数据来自 {effect_claims}。
如果资料没有真实数据，只用“体验反馈 / 肤感改善 / 使用感受”泛化表达，不编造百分比。
页面重点是证明 {function_1} 的变化感，产品小比例出现承接。
```

### 7. 研发体系背书

```text
生成一张研发/实验体系页。
主视觉为干净实验室、研究人员、检测流程、样本记录、仪器局部。
页面表达 {authority_assets} 和 {material_highlights} 中可用的研发背书。
可以出现泛化“配方测试 / 稳定性观察 / 肤感评估”等卡片。
不得编造真实机构、报告编号或医学临床结论。
```

### 8. 核心成分一机制

```text
生成一张核心成分页，只讲 {ingredient_1}。
标题写 {ingredient_1} + 一句消费者能理解的作用 {ingredient_1_benefit}。
主视觉使用该成分对应的原料、液体微距、分子感或机制示意。
画面解释它如何帮助 {function_1}。
不出现其他成分抢焦点，不写药品疗效。
```

### 9. 核心成分一证明/配比

```text
生成一张 {ingredient_1} 的证据补充页。
页面任务是解释为什么这个成分在本品里可信。
可展示浓度区间、配方搭配、安全肤感、清洁力、吸收力、稳定性测试等，具体依据产品资料。
中间用 2-3 张卡片或小图表承接，避免堆砌长文字。
没有真实数值时，不编造具体浓度和百分比。
```

### 10. 核心成分二机制

```text
生成一张第二核心成分页，只讲 {ingredient_2}。
标题突出 {ingredient_2_benefit}。
主视觉与第 8 屏不同，可以用屏障结构、舒缓场景、植物原料、质地包裹或微距切面。
说明它如何补充第一成分，形成“主功效 + 辅助护理”的配方逻辑。
```

### 11. 辅助功效机制

```text
生成一张通用辅助功效机制页。
不要固定写保湿或焕亮，而是从 {functions} 中选择最适合的第二层购买理由，例如舒缓、控油、保湿、提亮、紧致、修护、柔滑、清爽。
标题模板为“不止 {function_1}，更兼顾 {aux_function}”。
主视觉展示 {aux_function} 对应的成分、肤感或机制，配 3 个短解释点。
```

### 12. 辅助功效验证

```text
生成一张辅助功效验证页，承接第 11 屏的 {aux_function}。
使用测试卡片、局部对比、肤感评分、用户反馈或趋势图来表达“看得见的状态变化”。
如果有 {effect_claims} 中对应数据则引用。
没有则用泛化验证表达，不编造百分比。
画面应像可信的电商证据页，不像医疗报告。
```

### 13. 真人反馈合集

```text
生成一张真人反馈合集页。
使用 3-4 组局部前后对比或用户体验卡片，围绕 {target_user_pain}、{function_1}、{aux_function} 展示变化。
可以有“使用感更清爽 / 肤感更细腻 / 状态更稳定”等短句。
不得伪造真实用户头像、真实评价截图、真实平台评论。
```

### 14. 质地与肤感展示

```text
生成一张质地页。
主视觉为 {product_name} 的膏体/液体/泥膜/精华质地特写，展示延展性、清爽度、吸收感、易清洗或不黏腻等，按 {category} 适配。
底部放 3 个肤感标签：{texture_1}、{texture_2}、{texture_3}。
画面干净高级，产品清晰出现。
```

### 15. 品牌感/香氛/情绪价值

```text
生成一张品牌氛围收束页。
根据资料选择“品牌理念、香氛体系、原料来源、专家理念、使用仪式感”中的一个方向。
参考图可以是香调三段式，但不要固定香氛。
如果产品资料没有香味信息，就改为品牌理念或安心护理感。
画面要温和、有记忆点，避免空泛鸡汤。
```

### 16. 使用方法

```text
生成一张正确使用方法页。
用 3-4 步清楚展示 {usage_method}：取量、涂抹、停留/按摩、清洗/吸收等，按品类自动适配。
每步配真实动作图，人物自然，步骤标签清晰。
标题强调“正确使用，效果更好发挥”。
不要塞功效数据，不要做成说明书密集文字页。
```

## 八、单图生成总模板

每个详情模块生成时使用统一总模板，再注入当前模块 brief：

```text
你是电商护肤详情页视觉生成模型。
请生成 1 张竖版 9:16 中文商品详情页单模块图片。

【当前详情结构】
结构名称：证据链长图结构，16 屏
当前模块：{module_name}
模块序号：第 {module_index}/16 屏
页面任务：{page_task}

【产品身份】
产品名称：{product_name}
品类：{category}
核心卖点：{core_selling_points}
核心功效：{functions}
核心成分：{ingredients}
目标人群：{target_users}

【全局卖点方向】
首图主张：{cross_image_brief.hero_claim}
核心痛点：{cross_image_brief.primary_pain}
主功效：{cross_image_brief.primary_function}
辅助功效：{cross_image_brief.auxiliary_function}
可信证据：{cross_image_brief.proof_points}

【当前模块 brief】
标题方向：{headline_direction}
主视觉：{primary_visual}
必须出现：{required_content}
禁止出现：{forbidden_content}
资料来源说明：{data_source_note}

【画面要求】
只生成当前模块，不要拼成长图。
画面以一个核心视觉任务为主，不要把其他模块内容混入。
标题短、醒目、消费者能理解。
产品包装必须清晰，不能篡改 Logo、瓶身、标签和包装文字。
风格与整套详情页统一，但构图、主视觉和节奏要有变化。

【合规边界】
{compliance_boundary}
不得编造真实机构、检测编号、专利号、临床数据、医生背书、真实用户评价。
不得出现治疗、治愈、医学疾病改善、绝对化承诺。
没有真实数据时，不得编造百分比，只能使用体验型表达。

【负向要求】
不要廉价淘宝风、满屏文字、乱码、水印、夸张爆炸贴纸、医疗广告感、证书墙、真实竞品品牌攻击。
```

## 九、切换结构策略

如果用户已经解析过资料，又切换详情结构：

```text
详情结构已切换，需要重新拆解资料，才能生成新的模块 brief。
```

处理方式：

- 保留 `product_info`。
- 清空或标记过期 `detail_layout_brief`。
- 重新生成对应结构的模块 brief。
- `cross_image_brief` 可重新生成，因为不同详情结构的卖点优先级可能不同。
- 已生成图片不自动删除，但新结构下只展示当前结构对应模块。

---

## 十、验收标准

- 新建项目默认选择 `detail_evidence_chain_16`。
- 上传资料解析时会带上当前详情结构 ID。
- 新分支会生成 16 个模块 brief。
- 第 4 屏明确是“差评与竞品对比”，复用当前竞品对比逻辑，不写成多效适用。
- 第 11、12 屏是通用辅助功效机制和验证，不固定保湿、焕亮。
- 主图仍是 5 张，但能读取 `cross_image_brief` 的卖点、成分、证据和场景信息。
- 切回当前 10 屏结构时，老项目和旧模块顺序不被破坏。
